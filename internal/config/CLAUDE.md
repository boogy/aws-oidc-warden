# Config — Configuration Management

Extends [../../CLAUDE.md](../../CLAUDE.md). Viper-based loading, validation, and issuer-bound subject/condition matching (`config.go`).

## Loading

- `NewConfig()` loads once (`sync.Once`) and returns the shared instance.
- Precedence: `AOW_`-prefixed env vars > config file (YAML/JSON/TOML) > defaults.
- Nested keys map to underscores: `AOW_CACHE_TTL` → `cache.ttl`. See `example-config.yaml` for the full reference.

## Key structures & methods

- `Config` — `issuers` (`[]IssuerConfig`, v2 multi-issuer model; no legacy single `issuer`/`audience`/`audiences` fields), `default_issuer`, `role_mappings`/`role_groups`/`role_sets`, `config_fragments`/`config_fragment_checksums`, S3 config/policy buckets, logging, `cache`, `TagAuth`, `JWTValidation`, plus top-level hardening knobs.
- `IssuerConfig` — one trusted issuer: `issuer` (exact `iss` match, no normalization), `provider` (`"github"` = native claim struct unmarshal, `"generic"` = mapped-only via `claim_mappings`; default `"generic"`), `audiences` (ANY-match, ≥1 required), `jwks_uri` (optional override, skips OIDC discovery), `claim_mappings` (canonical field ← raw claim; `subject` is the only field the validator reads and the only one `Validate()` constrains — it may not point at `iss/aud/exp/nbf/iat`, identity-free claims that would collapse every caller onto one subject; `sub` is allowed and is the usual generic mapping. Other keys are ignored by the validator but their values still join the auditable-claim set, so they are accepted, not rejected), `required_claims`, `session_tags` (STS tag key ← raw claim; keys must match `[A-Za-z0-9 _.:/=+@-]{1,128}`). Non-`github` issuers must set `claim_mappings.subject`.
- Zero-config seed: if no config file/source is found (`viper.ReadInConfig()` returns `ConfigFileNotFoundError`) and `issuers` is still empty after unmarshal, `LoadConfig()` seeds a single default GitHub Actions issuer (`defaultGitHubIssuer()`). If a config source _is_ present but defines no issuers, `Validate()` hard-fails — the seed never masks a misconfigured file.
- Hardening knobs (top-level, all optional): `jwt_leeway` (default 30s, hard max 120s — `Validate()` rejects anything higher), `max_token_lifetime` / `max_token_age` (default 1h each; 0/unset applies the default, there is no "no cap" value), `max_token_bytes` (default 8192), `jwks_refetch_cooldown` (default 60s), `allow_insecure_issuers` (default false, dev-only escape hatch for `http://` issuer/jwks_uri). Env: `AOW_JWT_LEEWAY`, `AOW_MAX_TOKEN_LIFETIME`, `AOW_MAX_TOKEN_AGE`, `AOW_MAX_TOKEN_BYTES`, `AOW_JWKS_REFETCH_COOLDOWN`, `AOW_ALLOW_INSECURE_ISSUERS`.
- Logging/audit knobs: `log_level` (`debug`/`info`/`warn`/`error`, default `"info"`; `Validate()` rejects anything else), `log_claim_values` (default `true` — includes claim VALUES, e.g. the GitHub `actor` username, in structured logs/audit records; set `false` to suppress them, keeping only names/decision/reason), `audit_required` (default `true` — the operator's declared intent; `Validate()` never mutates it, so `AuditEnforced()` is the derived gate callers must branch on: it's `true` only when `audit_required` AND `log_to_s3=true` + `log_bucket` are set, making the audit-record write durable/fail-closed before an allow decision returns credentials. Without `log_to_s3`/`log_bucket` configured it's a boot-time warning, not a hard failure, and a later hot reload that supplies them re-engages enforcement without restating `audit_required`). Env: `AOW_LOG_LEVEL`, `AOW_LOG_CLAIM_VALUES`, `AOW_AUDIT_REQUIRED`.
- `Validate()` on `issuers`: at least one required; exact-match duplicate issuer URLs rejected; each needs ≥1 audience; `provider` restricted to `github`/`generic`; `claim_mappings` reserved-claim and `session_tags` charset checks run per issuer.
- `JWTValidation` — `Mode` (`"self"` default, `"apigw"`, `"alb"`) and `ALBExpectedSigner` (ARN of the trusted ALB; **required** in `alb` mode — `Validate()` fails without it, preventing cross-ALB token injection). Env: `AOW_JWT_VALIDATION_MODE`, `AOW_JWT_VALIDATION_ALB_EXPECTED_SIGNER`. `Validate()` rejects unknown modes.
- `RoleMapping` — `subject` pattern, `roles` (ARNs or `@role_set` names), optional `issuer` (defaults to `default_issuer`), optional `session_policy`/`session_policy_file`, optional `conditions`, optional `role_session_name` (per-mapping STS session-name override; falls back to the global `role_session_name` when empty; validated at `Validate()` against STS's 2–64 char `[\w+=,.@-]` charset).
- `Condition` — every key other than the four reserved ones names a **raw claim**: named fields `ref`, `ref_type`, `event_name`, `workflow_ref`, `actor`, `runner_environment`, `environment` plus a `Claims map[string]Patterns` (`mapstructure:",remain"`) for any other claim, any provider. The named fields are discoverability sugar — YAML behaves identically either way, and each is spelled exactly like its claim. Reserved keys: `all_of`/`any_of`/`none_of` (boolean groups, `[]*Condition`, nestable) and `claims` (`ExplicitClaims`), whose keys are ALWAYS claim names — the escape hatch for a claim named like a reserved key. v3 removed the three mismatched keys (`branch`, `actor_matches`, `environment`→`runner_environment`); nothing is deprecated-but-working, and `environment` now checks the `environment` claim. Every value is a `Patterns` (`patterns.go`) — a `[]string` that decodes from a scalar OR a list; patterns for ONE claim are OR'd, separate claims are AND'd. Lives in `condition.go`, not `config.go`. Every key compiles through the same anchored-regex mechanism (`compileConditionAt`/`compileAnchoredCondition`) into one AND'd `[]compiledCondition`, and on a single node that list and all three groups are AND'd together, so the top level is an implicit AND. An empty pattern or empty list is a hard `Validate()` error: it reads as a predicate but gates nothing. `satisfiesConditions` walks the tree recursively with no allocation and no compilation. Leaf matching goes through `claimMatches`: a string claim matches the anchored pattern, a `[]any` claim matches when ANY string element does, everything else (absent, null, number, bool, object) denies. `none_of` is exact negation, so a member naming an absent claim passes. `all_of`/`any_of`/`none_of` + nesting is functionally complete, which is why there is no `not`/`xor`/`n_of`.
- `RoleGroup`/`RoleGroupDefaults` — one entry expands to one `RoleMapping` per `subjects[]` entry, sharing `issuer` + `defaults` (roles/conditions/session policy).
- `RoleSets map[string][]string` — named, reusable role-ARN lists; referenced from a mapping's `roles` as `"@name"` (`resolveRoleSet` strips the `@` before the map lookup — map keys themselves must NOT include `@`).
- `Validate()` — compiles all regex patterns once; subject/condition patterns auto-anchored `^(?:pattern)$` and bare-wildcard-rejected (see Gotchas); resolves `role_sets`/`role_groups` into `effective` `RoleMapping`s and builds the per-issuer owner-bucketed `authzIndex` (`index.go`) over them. Bucketing (`exact`/`byOwner`/`any`) is performance-only, but that rests on **two** properties, not one: re-verifying every candidate against its own compiled pattern rules out false _positives_, while soundness of the bucket assignment itself rules out false _negatives_ — a mapping filed in a bucket `candidatesFor` never consults is simply never seen, and re-verification cannot save it. `classifySubject` therefore buckets `byOwner` only when the compiled program's `regexp.LiteralPrefix()` contains a `/`, so every string the pattern can match provably starts with `owner/` and hashes to the bucket `candidatesFor` looks in. Inferring the owner from the raw pattern text before the first `/` (pre-2.1.0) was unsound: a quantified first slash (`owner/?repo`, `owner/*repo`) also matches slash-less subjects, so the mapping was dropped from the scan — see `TestIndexParity`.
- `AuthorizeRoles(issuer, subject, claims)` — issuer-bound authorization lookup via the index; `FindSessionPolicy(issuer, subject, role, claims)` — applies the **same** predicates as `AuthorizeRoles` (subject match + conditions satisfied) **plus** `slices.Contains(mapping.Roles, role)`, so a role's scoping policy always comes from the mapping that authorized it; among qualifying mappings the lowest `order` (first-declared) wins, and `(nil, nil)` means no mapping grants the role (e.g. tag-auth, which by design carries no session policy). Resolving by subject alone — the pre-2.1.0 behavior — let an earlier broad mapping strip a privileged role's policy. `FindRoleSessionName(issuer, subject, role, claims)` resolves the per-mapping `role_session_name` override the same way — both it and `FindSessionPolicy` go through the shared `findAuthorizingMapping` so they can never disagree about which mapping authorized the role; `""` means the caller falls back to the global `Config.RoleSessionName`. `IssuerSessionTags(issuer)` returns the per-issuer `session_tags` spec consumed by `aws.BuildSessionTags`.
- `AuditableClaims(issuer, claimName)` (`auditable.go`) — per-issuer set of claim names that issuer's own config references: its `claim_mappings` targets, `required_claims`, `session_tags` targets, and every claim named by a condition (including inside `all_of`/`any_of`/`none_of`) on a `role_mapping` bound to it. Built once in `Validate()` into `Config.auditable`. `internal/handler`'s `auditClaims` uses it as the inclusion test for non-`github` providers, so a record can explain its own decision (the `groups` a `none_of` vetoed on is present) while a claim nothing references (`email`) never is. Names are stored as written AND lower-cased, and lookup tries exact then folded, because viper lower-cases every config KEY it reads while raw claim names keep their case.
- `TagAuth` (opt-in, default off) + `Authorize(roleTags, claims, verifiedIssuer, subject)` in `tagauth.go` — tag-based authorization fallback; exact matching only (AWS tag charset, no regex), space-list = OR, cross-tag = AND. Identity gate: the canonical `<prefix>subject` tag, or the legacy `<prefix>repo`/`<prefix>repo-owner` aliases (retained through the v2 migration window). Issuer gate: once more than one issuer is configured (`multiIssuer`), a role must also carry a matching `<prefix>issuer` tag or it fails closed (no cross-issuer identity collision); with a single issuer the tag is optional but still checked if present. Issuer-agnostic dimension: `<prefix>claim.<name>` matches the raw verified claim `<name>` (exact, space-list = OR, list claims match any string element) — every named suffix spells a GitHub Actions claim, so this is the only dimension a generic issuer has beyond `subject`. It is not an identity tag, so it can narrow but never grant, and it is matched case-SENSITIVELY: IAM stores tag keys verbatim, so unlike a `conditions:` key nothing is lower-cased on the way in and no case-folded fallback is needed. Full field set: `TagPrefix string` (default `"aow/"`), `DefaultOrg string` (expands bare `aow/repo` tokens to `<org>/name`; must not contain `/` or whitespace), `TransitiveSessionTags bool` (deprecated fallback for `Config.SessionTagsTransitive` below — kept only for existing configs, has nothing to do with tag-based authorization). See `docs/TAG_BASED_AUTHORIZATION.md`.
- `Config.SessionTagsTransitive bool` (top-level, `mapstructure:"session_tags_transitive"`, default off; RECOMMENDED to enable) + `Config.TransitiveSessionTags()` — the resolver `internal/aws` calls, ORing the top-level key with the deprecated `TagAuth.TransitiveSessionTags` fallback so either source enabling it wins. Governs whether every session tag attached to `AssumeRole` is marked transitive (`aws.selectTransitiveKeys`), so the caller's identity survives further role chaining instead of being dropped at the first hop. Off by default only for upgrade safety — transitive tags are immutable downstream, so enabling it breaks a target role that re-tags with the same keys while chaining. `Validate()` warns (never mutates) when the deprecated key is set but the top-level one is not.
- `CrossAccount` (opt-in, default off) — a **policy gate** for member-account role assumption: `Enabled bool` false (or the struct nil) hard-blocks every cross-account operation (both `AssumeRole` and, for `TagAuth`, `GetRoleTags`) — enforced in `internal/aws`, not here. Role assumption is always direct hub→target, one hop, using the warden's own credentials; `SpokeRoleName string` (default `"aow-spoke"`) + `ExternalID string` (optional) only configure the separate hub→spoke hop `GetRoleTags` uses to read a target role's IAM tags cross-account for `TagAuth` — never the assume path. `SpokeSessionDuration time.Duration` (default 15m) bounds that hop's session. `AllowedAccounts []string` (allow-list of member account IDs; hub implicit; empty = any once enabled; non-12-digit rejected by `Validate()`). Env: `AOW_CROSS_ACCOUNT_*`. See `docs/examples/cross-account/`.
- `Provider` — hot-reload wrapper around `Config`: `NewProvider(base, interval, format, fetch, ...ProviderOption)` / `NewStaticProvider(cfg)`; `MaybeRefresh(ctx)` does a lazy per-request reload (atomic swap from clone of pristine base) and re-resolves `config_fragments` on the same cadence; `Get()` returns the current active config. The token validator calls `Get()` on every `Validate()` so issuer/audience changes apply immediately.
- `config_fragments` (`fragments.go`) — additional sources merged onto the base config's `default_issuer`/`role_sets`/`role_mappings`/`role_groups` only (any other key is a hard error); local paths are content-hashed (sha256) for change detection and read directly; `WithFragmentFetcher(FragmentFetchFunc)` is the seam for remote (`"scheme://"`) sources, e.g. `s3://` — a failed/invalid fragment retains the last-good config.

## Gotchas

- Never compile regex per request — only in `Validate()`.
- `config_fragment_checksums` pins are compared on **every** refresh, before the unchanged-fragment cache-hit branch — so a pin added or rotated to quarantine already-applied content takes effect on the next reload rather than only on a content change.
- `Validate()` emits two non-fatal warnings for config shapes that are legal but silently do not mean what they look like: a role whose lowest-`order` grant carries no `session_policy` while a higher-order grant does (the policy is dropped — and across the `role_mappings`/`role_groups` boundary no ordering can fix it), and mappings bound to `default_issuer` while >1 issuer is configured (an overlay that adds an issuer and sets `default_issuer` re-homes every implicit grant).
- **`cloneCondition` must stay DEEP.** It recurses through `AllOf`/`AnyOf`/`NoneOf` via `cloneConditions`. A shallow copy leaves nested nodes shared across snapshots while `compileConditionAt` mutates them in place — a reader then sees a nested node's `compiled` list transiently empty, and an empty node is **true**, so the whole gate passes. A shallow clone still passes `TestHotReloadConditionRace` (flat condition); `TestHotReloadNestedConditionRace` is what pins the recursion. `cloneConditions` also preserves the nil vs empty-slice distinction, which is what lets `compileGroup` tell an absent `any_of` from `any_of: []`.
- **`Validate()` rejects the shapes that reduce a group to a constant**: an empty group list, and a group member that gates nothing (always true — it makes an `any_of` always pass and a `none_of` always fail). The **top-level** node gets the same check once its groups are compiled, so `conditions: {}` — and any block that compiles to no predicate, e.g. `environment:` written with no value — is rejected rather than authorizing unconditionally. A nil `conditions:` would otherwise never reach that check (the field is a `*Condition`, and nil is what an absent key decodes to), so `nilConditionHookFunc` (`patterns.go`) turns it into an empty node first — the same trick `stringToPatternsHookFunc` plays one level down, and the reason `DecodeNil` is set. Nesting is capped at `maxConditionDepth` (5, top level = 1) and one mapping's tree at `maxConditionNodes` (64) — both readability limits first and per-request-cost limits second, enforced only at load time.
- **`all_of`/`any_of`/`none_of`/`claims` are reserved keys under `conditions:`.** `Claims` is a `mapstructure:",remain"` map — it only ever collects keys no named field claimed — so adding a field takes that key away from it. The pre-v3 blast radius was narrow: the map was `map[string]string` and the package registered no decode hooks, so only a **string**-valued `any_of:` ever decoded, and such a config now fails to load loudly instead of changing meaning. A claim genuinely named like a reserved key goes under `claims:` (`ExplicitClaims`), which is compiled into the same AND'd list with a `claims.` error path. New `Condition` fields carry BOTH a `mapstructure` and a `json` tag, matching every existing field. The `json` tag is for consistency, not correctness — hot reload deep-copies `Config` through a JSON round trip (`cloneConfig`, `provider.go:317`) and `encoding/json` falls back to the field name, so an untagged **exported** field still round-trips. What silently drops a gate on the first reload is `json:"-"` (correct on the `compiled` cache, wrong on anything an operator writes) or an unexported field. `Patterns` also carries its own `UnmarshalJSON` for this path — the mapstructure hook does not run here. `TestNestedConditionsSurviveJSONClone` pins the round trip end-to-end rather than the tags.
- **Never compile a `*Condition` that another snapshot may be reading.** `compileCondition` mutates in place (`cond.compiled = cond.compiled[:0]`, then re-appends), and one `*Condition` can be shared across snapshots — a `config_fragment` reuses its parsed struct across hot reloads, and a `role_group` shares one `Defaults.Conditions` across every expanded subject. `appendEffective` therefore calls `cloneCondition(m.Conditions)` **before** `compileCondition`, giving each effective mapping private memory. Removing that clone reintroduces an authorization bypass: `Get()` readers hit `satisfiesConditions` unlocked, and a transiently-empty `compiled` list makes **all conditions pass** (regression test: `TestHotReloadConditionRace`). `appendEffective` takes `RoleMapping` **by value** — keep it that way, or the clone writes back into the shared struct.
- Keep patterns specific. A bare `.*`/`.+` is rejected by `Validate()` for **both** conditions (`compileAnchoredCondition`) and subjects (`compileAnchoredSubject`), sharing one `bareWildcards` set so the two cannot drift apart — a wildcard subject would grant its roles to every subject of the bound issuer. The check is literal by design: `(.*)` or `[\s\S]*` still compile, so it stops the accident, not a determined operator. Both `role_mappings` and `role_groups.subjects` route through `appendEffective`, so neither path can dodge it.
- Env keys are case-insensitive; config keys are snake_case. **Viper lower-cases every config key before unmarshal** (`insensitiviseMap`), which reaches the remain-map and `claims:` alike: a condition key `emailVerified` arrives as the claim name `emailverified`. The case is gone before mapstructure runs, so it cannot be recovered at load time; the lookup is reconciled at match time instead. `claimResolver` (`condition.go`) resolves a leaf's claim name **collision-first, then exact, then case-folded** over a lazily-built lowercased index. The collision check runs first and is deliberately **not** skipped when the exact lookup would succeed: the key reaching the matcher has already been lower-cased, so `iscontractor` is equally consistent with an operator who wrote `isContractor`, and an exact hit sitting alongside a differently-cased twin is still two candidate claims for one key with nothing to say which was meant. Preferring the exact one decides on a claim the config may never have named, and under `none_of` the twin disarms the veto outright — that is the same bypass reached through the other branch (`TestExactHitDoesNotResolveACollision`, `TestLowerCaseTwinCannotDisarmANoneOfVeto`). A collision therefore only sets `ambiguous` on the resolver; `satisfiesConditions` denies the **whole** evaluation once the walk finishes, rather than picking one claim arbitrarily. The deny has to be at the top and not at the leaf for the same reason the folded lookup exists at all: a leaf that merely fails to match is polarity-dependent, so under `none_of` it would disarm the veto instead of firing it. Absence and ambiguity are deliberately different — an absent claim genuinely gives a veto nothing to fire on, while an ambiguous one means the gate cannot determine the value it was told to gate on, and a gate that cannot know must deny. Checking on the resolver after the walk makes that independent of where the collision sat in the tree and of how many negations enclose it. Regression tests: `condition_ambiguous_test.go` (loads through the real YAML/viper path, since a Go-built `Condition` preserves key case and never reaches the folded index at all). The all-lowercase config — every GitHub deployment, since GitHub mints no upper-case claim name — is untouched and allocates nothing: `buildFolded` scans for a mixed-case name first and returns without building an index when there is none, so a collision is not even representable and every lookup answers from the raw claims (`TestAllLowerCaseClaimsTakeTheUnfoldedPath`). The folded fallback only fires where the answer would otherwise be an unconditional "no value". **This is not cosmetic.** Before 3.0.0 the miss was genuinely fail-closed, because every condition was AND'd and a leaf that cannot resolve denies. `none_of` inverts that: a veto whose claim can never resolve can never fire, so a mapping written to *refuse* `isContractor: "true"` authorized exactly the caller it was written to exclude. GitHub never exposed this — every GitHub Actions claim name is already lowercase. Regression tests: `condition_case_test.go` (unit table plus a full `NewConfig`→`Validate`→`AuthorizeRoles` end-to-end).
- **`DecodeNil` is set (`decoderOptions`) and its reach is narrower than it looks.** Viper's `AllSettings()` — what `Unmarshal` decodes — drops a null-valued **top-level** key entirely, so `audit_required: null` in an S3 overlay does not clobber the base value (`AllKeys()` still reports the key, which is why `MergeBytes` uses it for the issuers check). A null nested inside a non-null value _is_ carried through as raw data, which is the case that matters: `conditions:` and `ref:`. `TestMergeBytesNullKeysDoNotClobberBase` pins the boundary.
- Viper also decodes with `WeaklyTypedInput: true` (this package keeps viper's default `DecoderConfig` and replaces only `DecodeHook`, see `decoderOptions`). An unquoted scalar pattern is coerced, not rejected: `ref: 123` compiles to `^(?:123)$` and `ref: true` to `^(?:1)$`. Weak typing also lifts a map into a one-element slice, so `all_of: {ref: "x"}` loads as a one-member group rather than erroring — still compiled and still enforced, so it is a leniency, not a bypass.
- **Removed v2 keys do not fail to load.** `branch:`/`actor_matches:` now land in the remain-map as claims of those literal names. GitHub issues neither, so the mapping denies every request (fail-closed) and `warnConditionKeys` logs a WARN naming the key — for `provider: github` issuers only, since `knownClaimsFor` returns nil for any other provider. If that ever needs to be a hard load error, it belongs in `compileConditionAt`, not in the warning path.
- `WithFragmentFetcher` is defined but **not called from any production bootstrap path** — `internal/handler/bootstrap.go`'s `buildConfigProvider()` passes no `ProviderOption`s, so a `"scheme://"` `config_fragments` entry hard-fails to fetch in the shipped binaries today. Only local filesystem-path fragments work until a fetcher is wired in.
